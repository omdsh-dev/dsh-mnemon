# 从设置页迁移数据目录

[English](./README.md)

被测实现：`c94b3656`。Windows 11、Node 22.22.0、pnpm 11.7.0，由 `scripts/serve-e2e.mjs` 启动的真实 `dsh web` 实例，使用一次性 profile。图中目录是该 fixture 自己的一次性根；未使用任何个人记忆或凭据。

## 这一行给出记忆实际使用的目录，以及旁边的选择

在**插件 → dsh-mnemon → 存储**下，数据目录行显示记忆实际使用的目录，并提供**默认**与**自定义**两个选项。处于默认时它是一句陈述，不是输入框。

![数据目录行处于「默认」：记忆使用的路径，旁边是默认/自定义选择](./directory-default-zh.png)

## 「自定义」展开输入框、shell 自己的选择器与「应用」

选择**自定义**会展开路径输入框，旁边是 shell 自己的**选择目录…**按钮。应用那一行说明应用后会怎样，以及选好的目录可以一并把已有数据带过去。

![数据目录行处于「自定义」：路径输入框、选择目录按钮与应用那一行](./directory-custom-zh.png)

## 没有原生选择器的 shell 会直接说明

选择器是软依赖：一个提供了浏览式 picker、但没有原生目录对话框的 Web shell 打不开目录对话框，这一行会如实报告，而不是静默失败或丢掉已输入的路径。

![该行报告组合式 picker 不提供原生目录选择器](./directory-picker-unavailable-zh.png)

迁移本身——Host 先读出的计划、同时列出两个路径与将搬运的文件与字节数的确认框、对已占用或嵌套目标的拒绝，以及「全部文件校验通过前不删除任何数据」这一点——由 `tests/client-storage-review.spec.tsx` 与 `tests/storage-migration.spec.ts` 端到端驱动，因为该对话框需要无头 fixture 无法提供的原生选择器。
