# Issue #548：保留完整 Unicode 码点的记忆活动摘要

**简体中文** | [English](./README.md)

复现基线为 main `a4ad2d6955172b936ff9328f39cc5873c3ec9c55`。
记忆、请求和会话全部使用临时目录中的合成数据，未使用个人 Desktop Profile 或远端模型服务。

## 复现与结果

向 `mnemon_runtime_memory` 传入 158 个 ASCII 字符、`\u{1F600}` 和后缀。
修复前的活动标题包含这 158 个字符、不成对的高代理 `\uD83D` 和省略号。
`JSON.stringify` 只会转义非法代理字符，并不会修复它。严格校验 Unicode 的请求解码器
可能拒绝该转义字符串，正如 [#548](https://github.com/omdsh-dev/dsh-mnemon/issues/548) 所报告。

活动摘要现在复用 SDK 已有的截断函数。在这个边界处，补充字符会完整舍去，再添加省略号；
能够完整放入的码点则保留。UTF-16 长度限制、空白规范化、写入凭据和原始记忆正文均不变。
读取和写入摘要的标题、摘录、ID 及 View 引用共用同一处理路径。

## 回归证据

```sh
pnpm exec vitest run tests/activity.spec.ts tests/source-tool-lifecycle-host.spec.ts
```

- 修复前：8 个回归用例失败、17 个通过。
- 修复后：25 个通过，其中 12 个为新增用例。
- 真实已发布 DSH Host 执行覆盖 Runtime add 和 replace、后续模型步骤、第二轮对话以及
  JSONL 写入和重读。对解码后的持久化字符串检查 UTF-16 完整性，而非仅检查 JSON 能否解析。
- Runtime 快照保留完整原文，包括补充字符。还覆盖读取摘要、通用 View 写入、BMP 文本、
  恰好达到长度限制的字符串，以及能完整放入的代理对。

## 完整验证

macOS、Node 22.22.0 下 `pnpm run verify` 通过：主测试 2,399 项、组件测试 745 项，
分别保留 7 项和 3 项已有条件跳过。类型检查、文档检查、可重复构建、真实隔离
Headless Profile、公共入口导入、包内容、publint 和 attw 均通过。
已安装 DSH 的主测试还覆盖 `0.2.1-rc.5`（2,399 通过 / 7 跳过）和
`0.2.0-rc.2`（2,396 通过 / 10 跳过）。

旧 Host 首次运行出现 27 份 UI 测试收集错误：临时路径使用 macOS 的 `/tmp` 别名，
模块导入路径使用 `/private/tmp`，导致现有测试解析器的依赖回退未匹配。
改用 Host 的真实路径后，全套通过；未因此修改源码或依赖。
独立 review 复跑了 25 项定向测试，未发现必须修复的问题。

## 验证边界

此修复作用于新生成的 Mnemon 活动元数据，不改写已有会话历史，也不清洗其他插件传入的
任意畸形字符串。已受影响的会话需单独恢复；更新并重启 DSH 后，新会话仍可使用原有记忆。
本地模型适配器为脚本实现，未调用真实 DeepSeek 账号，也未操作报告者的 Windows 桌面安装；
不声称已验证外部服务返回 HTTP 200。展示长度保护 Unicode 码点，不保证包含多个码点的
字素簇一定完整显示。
