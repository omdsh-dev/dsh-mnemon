# v0.5.0-beta.1：Composable View Memory

**简体中文** | [English](../../en/releases/v0.5.0-beta.1.md) | [插件开发](../extensions.md)

本页是发行准备说明，不代表制品已经发布。v0.4 是独立的 Sidebar 收敛发行线；v0.5 以 beta 形式引入 View-based 模型与 Source/Strategy 扩展 SDK。

## 范围与兼容边界

- `dsh-mnemon` 仍是单包安装的 Starter。Runtime、Documents、Memory Spaces、默认 Strategy 与九种 Provider 拆为十三个独立插件。既有配置、存储格式、Sidebar/Buildin 页面和日常工具仍是用户侧兼容约束。
- Core 只暴露 `ctx.mnemonMemory`；作者通过 `dsh-mnemon/extension-sdk` 注册 Source/Strategy，通过 `dsh-mnemon/testing` 验证。Source 自有页面使用 Client SDK 与 DSH 生命周期。Memory Spaces 自己拥有 Provider SDK 与子 fiber，不增加 Core 级 Space 服务。
- Source 与 Strategy 是贡献职责，不强制分包：同一插件可在一个 Fiber 下成批注册二者。私有索引和维护仍归插件。动作词汇、副作用、结果表示和有限预算描述如何参与 View，不规定记忆树、五个接口或统一工作流。
- 每轮固定一个不可变 View。Source 操作只收到 View 身份/作用域与本 Source 的 read grant，不收到其他 Source 的投影和授权。Read grant 或 action offer 都不是写入许可。
- Source facts/projection 读取有超时边界与协作式取消。被选中的 Source 默认必需；只有显式 `required: false` 才允许缺席。故障的可选 Source 不再提供 route/action，并返回脱敏诊断解释缺席原因。公共指导跟随当前 View；自动三层复盘只属于 `default-three-tier`。

扩展 SDK 处于 beta，可能在 beta 版本间调整。官方包固定同一组已测试版本；外部作者应明确声明并测试兼容 peer 版本。早期实验 Source 若读取完整 `request.view`，需改用 `request.view.id`、`request.view.scope` 与自己的 `request.grant`。内部路径、历史符号和 Host RPC 不属于稳定扩展 API。

默认 Strategy 现在按语义属性选择已描述的操作，不再硬编码操作名称；未声明语义仍表示未知。变更回执必须说明完成状态：已受理和候选不等于已提交记忆，只有确认提交才能携带 `committedAt`。回执辅助函数默认 `unknown`；详见[操作与结果契约](../extensions.md)。

## 升级与回退

试用前停止写入，备份完整有效记忆根、工作区 Documents、DSH profile/配置和单独管理的 Provider 数据。在隔离 DSH profile 中用副本验证，不将 smoke test 指向个人记忆。本版不引入数据格式迁移。

等十四个制品实际全部发布后，显式选择 beta：

```sh
dsh plugin --profile web add dsh-mnemon@0.5.0-beta.1
```

Headless profile 将 `web` 改为 `headless`，然后重启 DSH。Starter 安装匹配的插件集，普通用户不需要手动安装十三个包。发布前使用[隔离开发夹具](../development.md)。稳定版用户不会通过 npm `latest` 隐式进入 beta。

采用副本前，确认原 Runtime 条目、Documents 检索/阅读、Provider 选择、召回/写入回执和设置正常。需要回退时，停止 DSH，同时恢复旧 profile 与配套数据备份，再启动。不能假定旧版本能理解实验性第三方插件新写入的数据。

## 有意保留的 beta 限制

默认 Host 通过 `memoryTopology.strategyId` 选择一个 Strategy，组合 root-turn View。本版不承诺通用多场景调度、自动发现/选择 Strategy、插件进程沙箱或自主 RSI 部署。Generation 替换与隔离作者测试为未来 RSI 提供基础，但不是自主进化闭环。外部插件执行受信任 JavaScript；取消无法抢占同步或不配合的代码。

发布门槛包括全工作区验证、所有独立插件仓库、纯 tarball 安装、外部 Source/Strategy/Provider/Client 测试、复制数据兼容、性能和真实 WebUI 检查。受控 HTTP 测试不代表所有线上 Provider 账号均已验证；固定模型响应也不衡量真实模型的记忆质量。参阅[验证与成组发布](../development.md)。
