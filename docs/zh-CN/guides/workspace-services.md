# 可组合的工作区服务

[English](../../en/guides/workspace-services.md)

可选工作区组合包含 16 个 Source：已有的 Runtime、Documents、Memory Spaces，以及 13 个可独立安装的工作区 Source。Starter 安装这些软件包，但默认关闭可选入口；按需启用并明确选择 `workspace` 策略。原有三层组合仍为默认值。

## 职责与组合

Source 自己管理存储、版本、建议、检索、修改、生命周期和页面；Memory Spaces 自己管理其 Provider 子插件。Workspace 是完整策略，选择公开能力并为一个 View 分配预算。它有六个独立增强插件：日志记录、审核周期、提示调度、团队协作、专注上下文和经验整理周期。增强插件通过 `dsh-mnemon-strategy-workspace/extension-sdk` 提交纯政策，不能运行程序、写文件、发消息，也不借用其他 Source 的权限。

`dsh-mnemon-workspace-kit` 发布通用记录、文件、附件和 DSH 适配工具。插件明确声明依赖，只导入公开出口。Host 负责通用操作的认证、路由、共享预算和注册页面的展示，没有新增业务插件白名单。卸载某个 Source 会移除其能力并保留数据。

## 组合设置

打开“设置 → 记忆系统 → 记忆插件”，可按能力搜索已安装插件，区分数据来源、主策略与策略增强。“发现能力”展示尚未启用的可选组件。启用前会列出依赖、策略切换和受影响的增强，一次应用全部变更；停用保留数据。需要多个候选提供者时应明确选择，管理器不会代选。

“安装其他插件”检查准确 npm 包名、版本以及 Core 和 DSH 的实际兼容范围，不兼容时不能安装。Starter 已登记的独立模块可直接更新；新插件需要可加载的 DSH bundle。安装调用当前配置所属的 DSH CLI，完成后明确提示重启，再刷新并启用。

打开“设置 → 记忆系统 → 组合策略配置”，选择主策略，再通过各增强功能的设置行切换开关或展开参数。字段来自所安装插件的公开声明。预览显示来源、读取、操作和上下文用量，需要时再展开具体来源的操作。保存仅提交已预览的同一份草稿，继续编辑后必须重新预览；“重新加载配置”会丢弃当前编辑器的草稿。

## 能力对应表

项目笔记和工作方法支持审核修订。点击“提出修订”编辑副本，原内容继续生效；在待审核队列中对照两个版本后采纳。模型必须先在当前 View 完整读取准确的原版。采纳会同时归档原版；如果原版已经变化，则拒绝此次采纳，需重新审核。批量采纳、拒绝和归档最多处理 50 条已选记录，检查每条版本，整批提交，不会部分生效。

经验与独立审核建议通过幂等转存接入其他 Source。已有同名技能时创建待审核修订，审核前保留原方法。经验页持续跟踪目标的采纳、拒绝、归档及替换状态。对话审核提醒与经验提取分别调度；独立审核器自行控制执行周期。

| 工作 | 负责组件 | 行为 |
|---|---|---|
| 偏好与工作上下文 | Runtime | 独立用户档案、作用域、版本历史与明确写入 |
| 项目约定与事实 | Project context | 分支范围、候选审核、重复信号去重、归档与恢复 |
| 完整项目文档与长期检索 | Documents；Memory Spaces | 文档生命周期与独立 Provider 存储，包含实际 Mnemon CLI |
| 项目进展、每日成果和反馈 | Journal | 日期与分支来源、原始反馈、成果记录、持久写入提醒 |
| 个人、工作、项目和每日任务 | Tasks | 审核、重要/紧急四象限、截止日期、状态历史、组合筛选与分页 |
| 可复用方法与技能 | Playbooks | 原生技能目录、配置目录中的 Markdown 编辑、启用状态、简介、标签与分类整理 |
| 提示词调用 | Playbooks；提示调度增强 | 变量预览、授权创建编辑、单次/持续/间隔调度、明确立即唤醒、使用与停止历史 |
| 本地资料 | Files | 明确目录、文件名/内容检索、有界读取、取消与真实路径检查；可用于检查指令文件 |
| 会话历史 | Sessions | 可见消息检索、配置 JSONL 导入、精确书签与相邻正文、完成轮次分叉及别名 |
| 普通会话操作 | Sessions；公开 DSH 适配器 | 创建、分叉、改名、投递、明确唤醒/引导、原生模型与预设、持久请求回执 |
| 团队协作 | Collaboration | 房间、成员、定向消息与图片、已读、在线状态、归档、文件/服务/便签资源声明 |
| 后台执行 | Agent Jobs | 配置 CLI 适配器、固定提示词/上下文/图片副本、审核计划、队列/日志/负载、取消/超时/重试/恢复和保留策略 |
| 会话审核 | Review；审核周期增强 | 持续独立审核员、仅可见对话、分层约束、提问/重置/历史、严重度及有来源反馈；建议转入目标 Source 的待审核队列 |
| 临时信息与素材 | Canvas | 持久自由便签、文件引用与上传副本、媒体预览、拖动/缩放/尺寸、作用域视角、稳定引用与有界模型读取 |
| 通知与渠道消息 | Notifications | 个人收件箱、可拖动铃铛、附件、经过审核的目标和渠道回执；支持配置 HTTP 桥或类型化传输适配器 |
| 跨设备数据 | Sync | 明确项目/全局导出范围、独立 Git 快照、三方冲突、本机/远端/两者保留和独立审核推送 |
| 上下文与界面设置 | Sessions；DSH UI | 公开容量提示、原生模型/预设设置、会话导航及响应式 Source 页面 |
| 安装版本与更新 | 既有 Host 与 DSH 插件管理 | 独立包元信息、profile 内更新和明确启用 |

分类由实际条目产生；重命名或移除只影响所选分类自己的项目或全局范围，保留正文与历史。新条目使用新分类后即可筛选该分类。提示词可按名称、精确分类、标签和简介共同筛选，并支持全文检索。立即使用固定一次，间隔为 0 也只使用一次；日期和时间变量在实际调用时按 UTC 展开。

## 启动独立开发实例

在使用已发布 DSH 依赖的独立检出中，指定本机 Mnemon 程序：

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm build:plugins
node scripts/serve-workspace.mjs --state-dir ../services --mnemon /absolute/path/to/mnemon --port 5279 --workspace-plugins
```

监督进程复制指定 Mnemon 二进制，隔离 `DSH_HOME` 和 `MNEMON_DATA_DIR`，将 profile、日志、数据库与合成工作区保留在 `--state-dir`。同时生成包含本检出与合成工作区的 `workspace.code-workspace`。通过 DSH“添加工作区”加入实际代码目录，即可操作隔离分支。首次访问应打开 `dsh web` 输出的完整 URL，以建立浏览器认证；直接打开不带认证信息的地址可能显示“authentication required”。输出的带认证 URL 属于本机访问资料，不应进入提交或截图。

固定模型和 CLI 测试程序用于检验编排。显式测试标记驱动经过审核的工具调用与合成 token 用量，不代表模型质量、外部计费或第三方账号实际送达。`--model configured` 使用调用进程的模型环境，不把凭证保存在仓库。Mnemon Native 按需运行真实 CLI，不需要常驻守护进程；嵌入服务另行配置。

向输出的监督进程 PID 发送 `SIGUSR2` 可保留数据并重启 DSH；停止监督进程会停止其子服务，但保留数据。完整重启监督进程会重新载入测试服务和 profile 生成逻辑。开发 patch 明确启用完整组合并扩大共享 View 预算；正式配置按实际需要选择 Source 与预算。

## 数据、权限与恢复

模型提出的记忆建议在采纳前保持待审核。会话、提示词、程序与外部消息动作分别检查权限，以及精确计划或版本。文件根和渠道来源均需明确配置；跨会话消息和审核意见保留插件来源。产生外部效果前先持久登记执行资格，不确定的任务或投递不会自动重放。

全局与自定义存储模式下，项目上下文跟随当前会话。工作区与集中式工作区存储模式提供独立检查选择器和对齐提示。数据存放位置与项目身份分别管理；切换工作区后，旧草稿和异步响应不能覆盖当前页面。

关闭 Source 保留其存储。改变数据根之前应导出或备份，切换根不会自动迁移。同步只传输声明的范围、保留历史、拒绝其他项目身份，且不会自动推送。调度中断保留已领取记录。清理需明确操作，保留活动任务和近期无引用附件。

原生集成使用公开插槽与服务。书签使用 Source 自己的精确阅读区，并提供独立原生会话导航，不替换宿主渲染器。CLI 适配器与通知桥是明确的集成入口，按需要配置已安装程序或渠道服务；保留的本地验收 profile 仅连接合成收件目标。

## 验证

```sh
pnpm verify
pnpm verify:plugins
pnpm release:intent
```

第一条命令检查文档、类型、确定性构建、全部插件与根测试、真实 Headless profile 及发布内容；制品检查将每个独立 tarball 安装到没有工作区链接的环境，验证外部消费者、Starter 升级和真实 DSH 多策略启用。实际结果、截图与边界见[WebUI 验收记录](../../workspace-context-validation.md)，职责标准见[实现清单](../../plans/composable-workspace-context.md)。

## 经验整理与数据回流

需要周期性改进时，在插件管理中开启**经验整理**和**经验整理周期**。Source 拥有证据、待审核建议、转存与明确反馈，增强负责调度；默认仍为原始三层记忆。在经验整理页检查证据、编辑并采纳建议，使用后记录帮助或问题。读取与模型自报使用单独显示。回流和自动采纳开关会持久化，失败或中断的整理保留未完成状态。全局偏好采纳需要两条独立人工证据。转入其他 Source 时仅创建一个目标待审核条目并保留关联，不会同时激活两份内容。

整理输入保留 Source 提供的执行状态、退出码、严重程度和来源归属。助手自述保持未经确认，失败、阻塞或取消不作为成功结果；退出码为零只证明进程完成。这些结果与明确反馈分别计数，不增加人工轮次。替换建议通过审核后才归档原条目并解除其待复核标记，同时保留纠正证据和历史。

可选插件页面共享 `dsh-mnemon/client` 的主题化页面、通知和指标控件；自定义布局应使用这些浏览器 SDK 组件。策略配置支持类型化布尔开关。
