# 技能管理

**简体中文** | [English](../../en/guides/skills.md) | [文档首页](../README.md)

**技能管理**把一个工作区能加载的 DSH 技能集中在一处：开关技能、在对话里使用、编辑、回到旧版本。它还能从你的真实对话中改进技能，每次改动先经过测试再由你采纳，并从技能已经发布的各个地方安装更多技能。技能管理目前是**实验性**组件：随 dsh-mnemon 安装并默认开启，自进化则要等你手动开启。

| 位置 | 能做什么 | 怎么打开 |
|---|---|---|
| [技能管理页面](#技能管理页面) | 管理技能、处理自进化的建议、测试技能、安装更多技能 | **记忆系统 → 技能管理**，或它自己的侧边栏入口 |
| [对话中](#对话中) | 看一个回合用了哪些技能、复盘提出了什么建议 | 回合结束后下方的**本回合技能**一行 |
| [设置](#设置) | 开关自进化及其参数、对话提示和侧边栏入口 | **插件 → 可组合记忆 → 技能管理**，或技能管理页面上的齿轮 |

技能是一个带 `SKILL.md` 的文件夹，采用 DSH 读取的 [Agent Skills](https://agentskills.io/specification) 格式。页面本身从不调用模型；技能只通过 DSH 自带的 `skill` 工具进入模型，技能管理不会往回合的记忆 View 里加任何内容。

下面的截图来自 [v0.5.34 技能管理图集](../../assets/skills-v0.5.34/README.md)，项目是虚构的 Lumen：助手用 `release-notes` 技能写版本说明，用户纠正了格式，之后的事交给自进化。

## 技能管理页面

页面有五个标签：**技能**、**进化**、**评测**、**市场**和**回收站**。**进化**上的数字表示有多少建议和草案在等你处理。

### 技能

![技能：按所在位置分组的技能，其中一个被覆盖；release-notes 有一条改进待处理](../../assets/skills-v0.5.34/zh-CN/skills-library.jpg)

列表按 DSH 的优先顺序，把能加载的每个 `SKILL.md` 按所在位置分组：项目的 `.dsh/skills`、`.agents/skills`，然后是你的 `~/.dsh/skills`、`~/.agents/skills`。同名技能只加载最靠前的一个，其余标为**被覆盖**。DSH 会拒绝加载的文件在列表下方计数（*N 个文件无法加载*），展开可见原因。

- 每行有一个**开关**，同时控制模型能否加载、`/` 菜单里是否出现；悬停时出现**使用**，点击回到对话并在输入框里填入 `/技能名`。行上的小圆点表示 DSH 实际加载的那份技能有改进在等待。
- **新建**按名称和描述在你选的位置写一个 `SKILL.md`；名称只能是小写字母、数字和单个连字符。
- 详情渲染 `SKILL.md`，提供**使用**、**编辑**和一个菜单：**生成改进草案**（由任务 Agent 写草案，可附上你的要求）与**移除**（技能文件夹移入**回收站**标签页）。
- **调用**是一个选项：**自动与 / 命令**、**仅 / 命令**、**仅自动加载**或**关闭**，写入的是 DSH 自己的 `disable-model-invocation` 和 `user-invocable` 键。
- **测试**是一行，显示用例数和上次得分，点击进入**评测**里的这个技能。**版本**和**文件**默认折叠：每次改动（新建、编辑、调用方式、安装、采纳的改进、恢复）都会留下一个版本，可以对比和恢复。

每次写入都以文件哈希为准：如果技能在此期间被别处改过，不会被覆盖。

### 回收站

**回收站**列出移除技能的名称、移除时间、原位置、技能目录或单个文件的布局以及大小。**恢复**把已知来源的条目放回记录的原路径；即使切换到其他工作区，项目技能仍恢复到原项目。旧条目没有可确定的来源时，需要先选择恢复位置。

同名技能已存在时，可以改名恢复、明确确认替换，或取消。替换会校验当前文件的哈希，并把被替换的技能保留在回收站。改名会更新技能名称并保留目录中的其他文件。操作后列表和数量会立即刷新。

**彻底删除**需要输入技能名确认，**清空回收站**也有单独的确认。这两种操作会永久删除文件；普通的**移除**会保留可恢复的文件。

### 进化

页面会跟踪进行中的草案和评测，在任务结束后再刷新一次卡片；回到窗口或浏览器标签页时也会重新读取状态。

**待处理**列出等你处理的内容：建议，以及直接为某个技能生成的草案。**已处理**保留已采纳、已忽略、已过期或已失效的建议。**证据**列出复盘读过的对话。星形按钮**复盘本会话**立即复盘当前对话，不必等它停下来。

| 建议及其证据 | 回测过的草案 |
|---|---|
| ![进化 · 待处理：改进 release-notes 的建议，展开了所依据的证据](../../assets/skills-v0.5.34/zh-CN/skills-suggestion.jpg) | ![建议下的草案：说明与改动、回测“当前 40 → 草案 93 +53”，以及差异](../../assets/skills-v0.5.34/zh-CN/skills-draft.jpg) |

- **建议**用一句话说明它要做什么（新建技能或改进某个技能），并附上理由、来自哪段对话和置信度。**生成草案**让任务 Agent 写出新的 `SKILL.md`；**忽略**则放到一边。展开**证据**能看到它引用的对话步骤，每一段都能跳到完整记录。
- **草案**展示说明与改动、一行回测结果（例如*当前 40 → 草案 93 +53*，点开是每个用例的判定）以及差异。**采纳**写入（新技能可选写到用户技能或项目技能），**放弃**丢弃，菜单里还有**编辑草案**和**按要求重写**。得分低于当前版本的草案，采纳前会再确认一次。
- **证据**把每段对话展示成编号步骤（你的消息、工具调用及其失败、技能加载），以及复盘在其上的标注。**置顶**可防止记录被清理；勾选若干步骤后点**生成**，可为某个技能生成测试用例。

![进化 · 证据：四段记录的对话；版本说明这段对话的信号与编号步骤](../../assets/skills-v0.5.34/zh-CN/skills-evidence.jpg)

### 评测

![评测：每个技能的用例数与最近得分；release-notes 的三个用例与逐个用例的回测结果](../../assets/skills-v0.5.34/zh-CN/skills-evals.jpg)

所有技能的测试集中在这里。列表先列有用例的技能（附上次在当前加载版本上的得分），再列没有用例的，最后是建议中提出、尚未创建的技能（**未创建**），后者可直接跳到对应建议。

- **添加用例**需要标题、用户会怎么说的任务、可选的背景，以及若干检查项，每项标为**必须**或**建议**。用例也会来自复盘和证据。每个用例有开关，展开可见检查项和来源对话。
- **运行回测**用启用的用例测试当前版本；技能尚未创建时，测的是不加载它的表现。回测记录保留最近几次，每次都能展开看逐个用例的判定、模拟执行的步骤和回答。

回测是模拟运行：执行者按技能写出它会怎么做，但不调用工具；评审逐项判定检查项。所有**必须**项都通过，用例才算通过；计分时**必须**项按两倍计算。对比时，任一侧未能运行的用例不计入双方得分。

用例需要截图、扫描件或图表时，在添加或编辑时勾选**依赖图片输入**。纯文本回测无法接收图片：标记的用例显示**未测**，不会调用执行者或裁判，也不计入本次得分和草案与基线的比较。选中的用例全部被标记时，回测完成但没有得分。这是用户明确设置的标记，不会自动识别图片需求，也不提供附件上传。

已有用例仍按纯文本评测，历史记录保持原样；请标记图片依赖用例后重新回测。如果改测转写的文字，可把内容填入**背景**并取消标记。降级到尚未支持此标记的 Host 前，请先关闭这些用例，避免旧 Host 继续模拟它们。

### 市场

![市场：搜索 changelog，已添加的来源中找到 1 个，skills.sh 找到 30 个](../../assets/skills-v0.5.34/zh-CN/skills-market.jpg)

| 来源 | 提供什么 |
|---|---|
| **精选**（内置） | 精选列表，附中英文介绍；每个技能都从上游仓库安装，许可证以上游为准 |
| **skills.sh**（内置） | `skills` CLI 使用的开放索引，收录数十万技能；输入两个字符以上即搜索，按安装量排序 |
| **GitHub 仓库** | 仓库（或其中一个文件夹）里的每个 `SKILL.md`，Claude Code 插件市场仓库也可以 |
| **网站** | 按 [Agent Skills 发现协议](https://github.com/cloudflare/agent-skills-discovery-rfc)在 `/.well-known/agent-skills/` 发布技能的网站 |
| **技能目录** | 市场自有格式的 JSON 文件（网址或路径），适合团队维护的精选列表，可带分类和中英文介绍 |

- **搜索**先过滤已添加的来源，下方再列出 skills.sh 的结果，附所在仓库和安装量。
- **来源**列出所有来源：每个来源显示类型、技能数和更新时间（或错误原因），带一个开关，菜单里有**刷新**和**移除**。**添加来源**接受 `owner/repo`、github.com 或 skills.sh 链接、网站地址、JSON 文件的网址或路径，并在抓取前就说明识别结果。把这些内容粘贴到搜索框，也会出现一键添加。
- **预览**展示 `SKILL.md`、文件列表、许可证和出处；skills.sh 审核过的技能还会显示**安全审核**，逐家列出结论（通过、需留意或未通过，问题最多的排在前面）。
- **安装**把技能写到你选的位置。文件取自技能所在的仓库或网站，完整获取，并限制大小和数量，所有路径都保持在技能文件夹之内；网站发布的压缩包必须与其公布的 SHA-256 摘要一致。安装会被记录，因此市场能提示更新，并在会覆盖本地修改时先说明。

|---|---|

Agent 会按技能内容执行，技能也可能带有脚本。只安装你信任的技能，并先看一遍 `SKILL.md`。

## 自进化

自进化默认关闭，可在[设置](#设置)里开启，或在**进化**标签的空白页上直接开启。开启后：

1. 每个回合结束时，Host 记录这一回合的步骤：你的消息、调用的工具及是否失败、加载的技能。令牌、API key 等机密会被替换掉。
2. 对话边进行边积分：每回合 1 分，较长的请求最多再加 3 分，较多的工具调用最多加 2 分，用到多种工具最多加 2 分。积分达到**复盘阈值**、对话空闲满**空闲等待**秒、且距上次复盘至少**复盘间隔**秒后，任务 Agent 在后台复盘。期间来了新的回合，复盘就顺延到下一次停顿。
3. 复盘寻找强信号（多次纠正、“以后都这样做”之类的指示、工具失败、换了做法、可复用的流程、技能缺失或误导、用户确认过的做法），据此提出新建或改进技能的建议，并标出所依据的步骤，也可以提出测试用例。选择新名称前，它会读取已有技能目录及最近更新的最多 20 条未完成建议，摘要和理由均有长度上限。复盘指令要求优先复用匹配的技能或建议，并在合并改进点时保留先前要求；是否匹配仍由模型判断，不是自动语义聚类。
4. 只有置信度不低于**最低置信度**的建议才会收下；同一技能名称、同一类建议只保留一条未完成的：新证据追加保留，待处理建议在新置信度不低于旧值时可更新摘要与理由，生成草案中或待审阅建议的文案不变；被忽略的建议，一天内不会再由同一段对话提出；每段对话最多保留**单个对话待处理上限**条；建议在**建议有效期**天后过期。改进类建议会记下技能当时的哈希，生成草案前文件被改动就会失效。
5. **生成草案**写出新的 `SKILL.md`。开启**草案自动回测**时，草案和当前版本（新技能则是不加载技能）用同一批用例比较，最多**每次回测用例数**个，结果显示在草案上。
6. 由你采纳、编辑、重写或放弃。没有你的**采纳**，任何技能都不会被改动。

复盘失败会记在对应回合下，并保留积分窗口；连续失败三次后，这段对话停止复盘，直到 DSH 重新创建它的 Agent。复盘、草案和回测都以 dsh-mnemon 任务 Agent 运行，使用**任务 Agent 模型**设置选定的模型，见[配置参考](../reference/configuration.md#后台任务-agent-的模型路由)。

## 对话中

![用到 release-notes 的回合，下方的本回合技能一行：release-notes · 建议 1](../../assets/skills-v0.5.34/zh-CN/chat-skills.jpg)

用到技能或获得复盘的回合，结尾会有一行**本回合技能**：先列出这一回合用到的技能（模型加载的，或你用 `/技能名` 调用的），复盘等待或进行时显示**复盘中**，完成后显示**建议**和条数。点击技能在技能管理页面打开它；点击建议打开那条建议，有多条时打开**待处理**列表。从历史记录重新打开的对话同样会显示这一行；没有内容可说的回合不显示。用**对话提示**开关可以关闭它。

## 独立的侧边栏入口

开启**侧边栏入口**后，技能管理会成为与记忆系统并列的独立侧边栏入口，记忆系统里不再显示它的标签。页面内容不变，只是有了自己的标题；齿轮打开它的设置，**返回会话**和**使用**回到对话，回合下方的链接也在这里打开。

|---|---|---|

## 数据与信任

- **技能就在 DSH 读取的位置。**编辑、安装和采纳都直接写技能文件夹；被删除或替换的技能先移入技能管理的回收区。
- **技能管理自己的数据**放在存储根目录的 `skills/` 文件夹：建议、草案和安装记录，测试用例和回测，记录下来的对话，每个技能的历史版本，以及市场来源和缓存。见[存储模型](../reference/storage-model.md#技能管理)。这些数据不在 ZIP 备份和 Git 同步之内。
- **记录的对话**只保留复盘需要引用的内容（你的消息，工具名称、参数和失败，技能加载），机密会被替换。最多保留最近 100 段；置顶的、被建议或用例引用的保留得最久。任何一段都可以删除。
- **任务及子代理会话**由 DSH 保存在自己的会话目录（默认 `~/.dsh/sessions/`，实际位置取决于 DSH 配置），与上述 `skills/` 证据记录分开。一次复盘涉及任务 Agent 和委派的执行子代理；释放实例、侧栏隐藏或删除技能证据记录都不会自动清理这些 DSH 会话。Mnemon 当前没有会话清理入口或自动保留期限，它们也不在 Mnemon ZIP 备份或 Git 同步范围内。关闭**自进化**会停止后续自动复盘，不会删除历史记录；手动生成草案、回测等模型操作仍会创建会话。
- **模型调用。**只有自进化、生成草案、回测和从证据生成用例会调用模型，均以任务 Agent 运行；浏览、编辑、开关和安装都不会。
- **市场**会访问 GitHub、skills.sh 和你添加的网站。GitHub 对未认证请求每小时限 60 次；列出一个仓库用一次，并在十分钟内复用。在 DSH 的运行环境里设置 `GITHUB_TOKEN` 或 `GH_TOKEN` 可以提高这个上限。

## 常见问题

| 现象 | 处理 |
|---|---|
| **进化**一直是空的 | 确认已开启**自进化**。一段对话需要几轮实际工作和一次停顿才会第一次复盘；可以用**复盘本会话**立即复盘。 |
| 回合下显示**复盘失败** | 任务 Agent 没能给出结果，积分窗口会保留到下一次。连续失败三次后，这段对话停止复盘，直到 DSH 重新创建它的 Agent。 |
| 提示 *GitHub declined to list …* | GitHub 本小时的额度已用完。稍后再试，或设置 `GITHUB_TOKEN`。skills.sh 的预览仍会用它保存的文本副本展示技能，并注明这一点。 |
