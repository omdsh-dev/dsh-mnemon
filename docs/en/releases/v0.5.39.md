# v0.5.39: Reliable Memory Turns and Current DSH Support

[简体中文](../../zh-CN/releases/v0.5.39.md) | **English**

This patch release includes #543–#547 and #549.

- **Usable memory in accepted turns:** recover the current View before an accepted Agent step when another plugin short-circuits prompt assembly. Native and PTC reads, later turns, resumed sessions and delegated children keep the existing authorization boundaries (#544; fixes #542).
- **PTC history integrity:** check automatic-review admission during the awaited turn-stopping hook and drain its execution before the turn ends. Idle timers consume the result without executing tools in the completed parent turn. A copy-only recovery path recognizes the specific paired out-of-turn probes in affected unseeded root v4 sessions (#545; fixes #541).
- **Unicode activity summaries:** truncate titles, excerpts and other bounded activity fields without splitting a surrogate pair. Complete memory content is preserved, preventing newly written metadata from causing subsequent model requests to fail (#549; fixes #548).
- **Git sync authors:** the Default identity follows effective Git configuration before using the historical fallback. Custom identities remain explicit; safe retries do not rewrite published Git history (#543; fixes #539).
- **Skill draft destinations:** choose user scope, project scope, or derivation from storage scope. The upgrade default remains user scope. Explicit adoption choices win, edits stay with their existing skill, and unavailable project destinations fail without silently switching roots (#546; supports #540).
- **Current DSH contracts:** use the rc.5 development cohort and support alpha.2's public executor and tool-batch APIs. Earlier supported releases stay in the verification matrix (#547).

## Upgrade and compatibility

Use **Memory System → Status → Check versions → Update**, then restart DSH. For a fresh exact Web-profile installation:

```sh
dsh plugin --profile web add dsh-mnemon@0.5.39
```

The compatibility matrix retains DSH **0.2.0-rc.2**, **0.2.1-rc.2** and **0.2.1-rc.3**, with **0.2.1-rc.5** as the current RC baseline and **0.2.2-alpha.2** tested separately. The RC and alpha remain upstream prereleases. For the alpha on macOS, use the fully verified **Node 24.22.2** environment; earlier Node 24 versions have separate build/runtime limitations described in [compatibility](../reference/compatibility.md).

Existing memories and settings need no migration. Upgrading prevents new malformed session records; it does not automatically repair old histories. For the specific PTC corruption, follow the [copy-only recovery procedure](../reference/compatibility.md#ptc-idle-review-history-recovery), retain the original backup, and validate the copy with the same DSH version before any offline replacement. Existing Unicode-corrupted conversations require separate recovery; a new conversation can continue using the intact memory.

Rollback uses the previous Starter's complete pinned composition and restores the old bug behavior. No existing skill files are moved by the new destination setting.
