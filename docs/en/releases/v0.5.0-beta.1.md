# v0.5.0-beta.1: Composable View Memory

[简体中文](../../zh-CN/releases/v0.5.0-beta.1.md) | **English** | [Extension guide](../extensions.md)

Release preparation, not an announcement of published artifacts. v0.4 is the separate Sidebar-convergence line; v0.5 introduces the View-based model and Source/Strategy extension SDK as beta.

## Scope and compatibility

- `dsh-mnemon` remains the one-package Starter. Runtime, Documents, Memory Spaces, the default Strategy and nine Providers ship as thirteen independent plugins. Storage formats, existing workflows and normal tools remain the user-facing contract. Main's v0.4.3 behavior is retained: Sidebar by default, optional Builtin placement of the same Source pages, automatic `buildin` → `builtin` preference normalization, and the collapsed Sidebar icon fix. No memory data is migrated or deleted.
- Core exposes `ctx.mnemonMemory`; authors register Sources/Strategies through `dsh-mnemon/extension-sdk` and verify them through `dsh-mnemon/testing`. Source-owned pages use the Client SDK and DSH lifecycle. Memory Spaces owns its Provider SDK and child fibers; there is no additional Core-level Space service.
- Source and Strategy are contribution roles, not compulsory package boundaries: one plugin may register both in one Fiber-owned batch. Private indexing and maintenance remain plugin-owned. Operations remain open: no universal memory taxonomy or tree is required.
- Each turn pins one immutable View. Source operations receive only View identity/scope and their own read grant, not another Source's projection or grants. A read grant or action offer never grants write authorization.
- Source facts/projection reads have bounded time and cooperative cancellation. Selected Sources are required by default; `required: false` explicitly permits omission. Failed optional Sources contribute neither routes nor actions, and sanitized diagnostics explain their absence. Generic guidance follows the active View; automatic three-tier review belongs only to `default-three-tier`.

The extension SDK is beta and may change across beta releases. Official packages pin the same tested version; external authors should test and declare compatible peer versions explicitly. An earlier experimental Source that read a full `request.view` must use `request.view.id`, `request.view.scope` and its own `request.grant` instead. Internal imports, historical symbols and Host RPC are not stable extension APIs.

Mutation receipts must state their completion: accepted ingestion/candidates are not committed memory, and only confirmed commits carry `committedAt`. The receipt helper defaults to `unknown`; see the [operation and result contract](../extensions.md#open-operations-bounded-execution).

## Upgrade and rollback

Before trying the beta, stop writers and back up the complete effective memory root, workspace Documents, DSH profile/configuration and any separately managed Provider data. Test against copies with an isolated DSH profile; do not point a smoke test at personal memory. No data-format migration is introduced by this release.

After all fourteen artifacts are actually published, opt in explicitly:

```sh
dsh plugin --profile web add dsh-mnemon@0.5.0-beta.1
```

Use `headless` instead of `web` for that profile, then restart DSH. The Starter installs the matching plugin set; normal users do not install thirteen packages by hand. Before publication, use the [isolated development fixtures](../development.md). Stable users do not enter beta implicitly through npm `latest`.

Verify existing Runtime entries, Document search/read, Provider selection, recall/write receipts and settings before adopting the copy. To roll back, stop DSH, restore the previous profile and matching data backup together, then restart. Do not assume an old version understands data newly written by an experimental third-party plugin.

## Deliberate beta limits

The default Host selects one Strategy with `memoryTopology.strategyId` and composes its root-turn View. Generic multi-scenario scheduling, automatic Strategy discovery/selection, plugin process sandboxing and autonomous RSI deployment are not promised. Generation replacement and isolated author tests provide useful building blocks for future RSI; they are not an autonomous evolution loop. External plugins execute trusted JavaScript, and cancellation cannot preempt synchronous or non-cooperative code.

Release gates are the full workspace verification, all independent plugin repositories, tarball-only installation, external Source/Strategy/Provider/Client tests, copied-data compatibility, performance and real WebUI checks. Controlled HTTP tests do not certify every live Provider account; a fixed model stub does not measure real-model memory quality. See [verification and coordinated publication](../development.md).
