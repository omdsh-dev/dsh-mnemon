Keyword search finds exact text in OpenViking spaces (#452). Direct search and Ask Agent with Keyword search, and `mnemon_recall` in keyword mode, now go through OpenViking's `search/grep`, so an ID, a version, a path or an error code is found by its exact text instead of by meaning. Up to 8 terms, or double-quoted phrases on one line, are matched literally and in any case, but not from inside a number or a word: `29.8.5` does not match `29.8.50`, while `5.2.2` matches `v5.2.2`. Chinese and other text without spaces matches anywhere, and a hexadecimal ID of 7 or more characters matches by its start. When one grep for all the terms fills up, each term gets its own, so a common term cannot crowd out a rare one, and the result names a term that fills its own. Memories holding rarer terms, and more of them, come first, and the latest of memories holding the same terms leads. Smart recall and Basic match are unchanged. A server without `search/grep` answers keyword searches semantically and says so.
